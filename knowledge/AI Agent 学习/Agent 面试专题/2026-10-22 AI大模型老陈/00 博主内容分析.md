# AI大模型老陈的内容分析与面试价值

截至 2026 年 10 月 22 日，已核对[AI大模型老陈主页](https://www.xiaohongshu.com/user/profile/65d2c79600000000050335eb)的 60 条可见标题，抽读 7 篇笔记。其中 3 篇读取完整文字正文，另外 4 篇逐张核对了共 18 张图片。以下结论针对这组样本。

这个账号适合作为 Agent 工程面试的问题来源：它能提醒候选人解释选型、失败处理、上下文和评测。技术图解的精度不一致，公司面试故事与招聘结果也没有得到独立确认，因此参考答案仍需另行核验。

## 对面试能力的理解

最值得保留的是把项目经历分成三个层次：实现了哪些功能、为什么作出这些设计选择、如何处理运行中的失败。S2 对功能演示和工程解释作了明确区分；S1 则把风险边界、调用工具的条件、错误分类和评测指标串成一次面试追问。这组问题能检验候选人是否理解系统如何运行，而不只是在复述框架名称。[项目追问 S2](https://www.xiaohongshu.com/explore/6ab48a53000000001802e188)，[工程判断 S1](https://www.xiaohongshu.com/explore/6ad9d0030000000032014ee8)。

这个方向有工程依据：Agent 会动态选择行动，任务越开放，成本、延迟和错误累积越值得控制；是否引入自主决策应当由任务需求决定。[Anthropic 的架构说明](https://www.anthropic.com/research/building-effective-agents)。

它对不同岗位的区分还可以更清楚。S4 同时包含企业服务架构、记忆、MCP、产品拆解和 Transformer 计算题，适合作为能力地图；准备顺序仍应依据目标岗位调整。应用开发优先理解执行链和验证方法，推理服务岗位再提高缓存和模型计算题的权重。[S4 的四张题目图](https://www.xiaohongshu.com/explore/6a9a8cb8000000001203f908)。

## 需要修正的技术表述

### LangGraph 与 Function Calling 的比较需要补齐层次

S2 提出选择 LangGraph 还是原生 Function Calling。更准确的比较是“自己编写调用循环”与“采用编排运行时”。Function Calling 表达模型请求的工具及参数；LangGraph 管理状态、控制流、持久化和恢复，两者可以同时使用。[原笔记 S2](https://www.xiaohongshu.com/explore/6ab48a53000000001802e188)，[LangGraph 官方定位](https://docs.langchain.com/oss/python/langgraph/overview)。

### Prefix caching 的收益不能限定为 Attention

S4 第 11 题把 Prefix caching 只优化 Attention 当作前提，需要改写。以因果 Transformer 的常规前缀 KV 复用为例，缓存存储的是各层 K、V；命中后可以跳过共享前缀的重复预填充计算。由此可推导，被省去的计算也包括为这些前缀位置重新执行的 FFN。新后缀仍须正常前向计算。

“存储什么”与“省去哪些计算”必须分开。Prefix caching 主要减少重复 prefill，不意味着生成每一个新 token 都因此加速。[原题 S4](https://www.xiaohongshu.com/explore/6a9a8cb8000000001203f908)，[Hugging Face 缓存原理](https://huggingface.co/docs/transformers/main/cache_explanation)，[vLLM 前缀缓存与收益边界](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)。

### 五种模式是整理方式

S5 把 ReAct、CodeAct、Agentic RAG、Self-Reflection、Multi-Agent Planner 并列展示。它们分别描述行动循环、行动表达方式、检索策略、反馈机制和协作结构，可以组合使用。例如，一个 ReAct 循环可以执行代码动作，也可以调用检索工具。[原图 S5](https://www.xiaohongshu.com/explore/6a58e4a1000000000f02b03a)，[CodeAct 原始论文](https://arxiv.org/abs/2402.01030)。

图中 Agentic RAG 更可靠、自我反思能降低错误等优点，应当改成带条件的效果假设。S5 没有给出对应评测；历史研究也发现，无外部反馈的自我纠错可能变差。这不代表当前所有模型都会失败，而是说明不能由“多反思一次”推出必然更正确。[自我纠错研究及其限定范围](https://arxiv.org/abs/2310.01798)。

S5 的 ReAct 示例还出现了具体的不一致：问题问美国人口，工具示例和返回结果却转成了加拿大人口。图示可以帮助理解循环，但这个例子没有验证任务完成。

### Skills 不自动强制固定流程

S6 把 Skills 类比为操作手册，适合入门。但指令本身不保证逐步执行；需要强约束的步骤仍应由程序校验。Skill 可以包含指令、脚本和参考资料，并按需加载。MCP 则规定上下文交换，也包含 tools、resources、prompts 等能力。[原图 S6](https://www.xiaohongshu.com/explore/6a4ca8c80000000011004ca8)，[Agent Skills 标准](https://agentskills.io/home)，[MCP 架构](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture)。

### 调用更少需要结合任务质量判断

S1 用调用次数和成本讨论优化，是有用的工程入口。不过调用次数只是诊断指标：减少必要检索也会减少调用，却可能使答案失真。原文的调用与成本改善是博主叙述，未附可复现评测，不能据此推导一般收益。[S1](https://www.xiaohongshu.com/explore/6ad9d0030000000032014ee8)。

## 招聘和教学宣传如何理解

主页出现多条招徒、转行、薪资和拿 offer 的标题；S1 作者置顶评论明确引导关注、留言和加入训练营。因此，这个账号也承担教学招募功能。现有样本不能独立确认其面试官身份、收入、候选人故事或企业录用结果。

S3 的主体是求职动机、经验不足时的表达和职业规划，不能据此确认某公司的技术面试风格。使用这类模板时，要把企业宣传词换成已核对的岗位要求与本人真实证据，尤其不能照抄已经实现量化效果等经历。[S3](https://www.xiaohongshu.com/explore/6aa27715000000002902ca37)。

## 面试准备顺序

下面按对 Agent 应用开发的复用价值排序。次数是本次 7 篇样本的主题覆盖篇数：实质讨论计入，单纯出现名词不计；同篇只计一次。它既不是原题逐字重复数，也不是独立面试次数。重要性不按次数机械排序。

| 顺序 | 精选主题 | 覆盖篇数 | 来源 | 优先理由 |
| --- | --- | --- | --- | --- |
| 1 | 何时使用 Agent 或固定流程 | 2 | S2、S4 | 决定是否需要自主决策，影响整个架构 |
| 2 | 工具失败、恢复和重试边界 | 2 | S1、S2 | 检验系统能否处理真实失败 |
| 3 | 评测、成本和优化证据 | 3 | S1、S2、S4 | 判断改变是否有效，防止只凭演示评价 |
| 4 | 上下文与长短期记忆 | 3 | S2、S4、S7 | 多轮任务的核心状态问题 |
| 5 | 权限、隔离和人工确认 | 3 | S1、S4、S5 | 界定执行能力与错误后果 |
| 6 | MCP 的职责及组件分工 | 2 | S4、S6 | 防止把协议、技能和运行时混为一谈 |
| 7 | Agent 模式的条件和代价 | 1 | S5 | 用机制比较方案，避免只记名称 |
| 8 | KV cache 与 Prefix caching | 1 | S4 | 连接模型推理与系统性能，岗位相关时提高优先级 |

各题的考察意图、因果推导、参考回答和追问见[重点题目与参考答案](<01 重点题目与参考答案.md>)。
