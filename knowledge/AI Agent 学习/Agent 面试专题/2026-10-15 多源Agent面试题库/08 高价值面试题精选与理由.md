# Agent 高价值面试题精选与理由

针对 Agent 应用研发与 AI 后端，我建议先深入准备下面 12 题。面经的主要价值在于暴露追问方式，公开题库适合补齐知识地图；准备效果最终取决于能否解释机制、做出取舍、定位失败并提出可信验证。

这些题按当前准备价值重新排序，原题号保留。选择依据是与目标岗位的相关性、对其他知识的组织作用、决策造成的实际影响，以及能否用证据检验回答。原 144 题的来源次数、完整答案和频次辅助排序继续保留。复核日期为 2026 年 10 月 17 日，题目次数沿用 10 月 15 日的固定样本，没有补算新频率。

## 面经内容的价值判断

真正有用的面经会把问题追到机制、适用条件和验证。例如[牛客这则面试自述](https://www.nowcoder.com/discuss/932295617999622144)从混合检索追到 RRF、重排和跨领域表现，并问评测集及项目指标。它提供了一条值得准备的追问链；个人自述不能据此代表整家公司统一标准。

小红书内容也有不同用途。[Freya 的场景与转岗讨论](https://www.xiaohongshu.com/explore/6a953e95000000001e016fd8)适合提醒准备选型、限制、可靠性与项目闭环；[算法小登的作者评论](https://www.xiaohongshu.com/explore/6a159aa80000000035027199)提醒题目会随简历和项目改变；[Offer面试官的文字题单](https://www.xiaohongshu.com/explore/69b65422000000001a0312bc)适合发现检索、工具、安全和传统后端知识的交叉。前两者中这些观点不能作为实际问过某题的次数。

[程序员峰哥](https://www.xiaohongshu.com/user/profile/63572290000000001901d19a)目前可核对的是部分主页标题及文字；图片中的完整原题未读取，不能评价其全部答案质量。X 线索的正文访问受限，也不能作为已核验面经。GitHub 收录有助于查漏，但“被多个仓库收录”不能证明公司高频考察或答案准确。

对技术判断，我参考了 Anthropic 对[固定流程与自主控制的区分及先做简单基线的建议](https://www.anthropic.com/engineering/building-effective-agents)，以及其[Agent 评测中任务、轨迹与环境结果的区分](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。这些是一手工程材料，用于核对机制，不计入面经次数，也不能证明本精选的预测命中率。

### I02

**精选问题：** 怎样避免重试造成重复业务效果

**原题：** 如何防止重复发信、重复扣费和重复创建业务对象？

**为什么有价值：** 它检验能否处理有副作用的真实系统。超时只说明未按时拿到响应，不能推断动作未发生；这一点会决定重复创建、重复发送等问题能否恢复。

**参考回答：** [[knowledge/AI Agent 学习/Agent 面试专题/2026-10-15 多源Agent面试题库/01 Agent 面试题库144题#I02|引用主维护页的回答]]

**需要准备到的程度：** 区分一次尝试与一个逻辑动作，说明稳定业务键、并发约束、持久状态、未知结果核对及跨系统边界。

**容易停留在表面的回答：** 统一重试三次，或每次重试都生成新的幂等键。

**可用的对照例子：** 构造服务已完成但响应丢失的场景；重试应复用同一业务键，并查询原动作状态。仅在本地记一条成功记录，不能保证外部服务只执行一次。

下面两题与当前业务背景相关，可用于把前面机制串成一个设计案例。它们是工程补充，在当前面经与公开题库样本中均为 0 次，不标成博主原题。

### R03 广告创意工作台怎样划分程序与模型的职责

**题目：** 设计广告创意工作台，哪些步骤固定，哪些交给模型决定？

**为什么适合当前准备：** 它把自主程度、资料使用、状态保存与人工判断放进同一条业务流程。能说明每个组件解决了什么问题，就能减少堆砌工具名称。

**参考回答：** 我会先定义交付：给定 brief 和有效资料，输出有差异的创意方向及可编辑草稿，保留版本与依据。固定程序负责资料权限、状态保存和硬约束；模型负责结构化 brief、生成方向，以及有必要时选择检索或生成工具。语言规划、视觉理解、图像生成和程序排版分工，事实审核与主观创意评价分开。用同一批虚构任务比较直接生成基线，评估约束满足、方向差异、修改量、时间和成本；没有投放数据就不声称转化提升。

**追问：怎么证明比一次直接生成更好？**

在同批虚构 brief 上比较约束满足、方向差异、人工修改量、时间与成本，主观评分需校准。

**追问：必须使用多 Agent 吗？**

不必须。先用一个模型加明确工作流；只有专业上下文隔离或并行能带来可测收益时再拆分。

### Q06 创意质量怎样与事实和品牌约束共同验收

**题目：** 如何评价创意多样性、品牌一致性和事实正确性？

**为什么适合当前准备：** 它检验能否把可核对的硬约束与需要人判断的创意质量分开，并解释评审标准是否真正测到了目标。对创意工作台，这比只给一个模型总分更有用。

**参考回答：** 我会把创意评测拆为硬约束和需判断的质量。事实、必须文字、尺寸与有效版本可以明确核对；方向多样性、品牌一致和表达质量则用量表及人工校准，模型评分只作辅助。多样性要看洞察、主张、执行机制和视觉概念，而不只看换词。例如三个标题都讲工作间隙休息，即使措辞不同，也可能只有一个方向。比较方案时隐藏版本、允许平局并保留分歧，同时统计人工修改量、时间与成本；没有真实投放实验就不声称点击或转化提升。

**追问：三个文案措辞不同，是否代表三个创意方向？**

未必。要比较洞察、传播主张、执行机制和视觉概念，而非只看字面差异。

**追问：事实准确但创意平庸，应该算成功还是失败？**

分别报告维度，并依据事先定义的交付标准判断总体是否达标；不能用高创意分抵消严重事实错误，也不能用格式通过掩盖方向不足。

## 按岗位再展开的题目

| 题目范围 | 什么时候值得深入 | 准备时抓住什么 |
|---|---|---|
| E01 至 E04 混合检索 RRF 重排与数量选择 | 目标岗位以知识检索或 RAG 为核心 | 讲清旧方法的问题、机制和代价，用任务集确定参数；解释领域变化时怎样验证。固定背一个 Top K 数值没有通用依据。 |
| D01 至 D03 文档解析与分块 | 项目包含 PDF 扫描件或复杂表格 | 用实际解析错误解释内容、层级、表格和元数据怎样进入索引，再讨论分块策略。 |
| G01 至 G06 协议 Skills 与框架 | 职位明确需要工具生态或相应框架 | 先讲解决什么连接与运行问题、边界在哪里，再准备当前版本细节；不要只背名词对照和 SDK 方法名。 |
| J01 至 J08 多 Agent | 存在并行需求 专业上下文隔离或复杂协作 | 先比较单 Agent 加工作流的基线，再解释拆分收益、通信代价及失败恢复。 |
| N 模型适配与推理优化 | 算法或推理服务岗位明确要求 | 训练目标、数据、推理资源和实验方法都重要，应按岗位单独深化；当前应用准备无需等量展开。 |
| O 与 P 后端基础和手写代码 | 后端职位或编码轮次要求 | 数据库、并发、队列和算法仍需准备；能口述 Agent 题不能代替这些能力。 |

## 怎样使用这份精选

第一遍读完整参考回答，建立问题之间的联系：A01 决定控制方式，F01 和 I02 解释动作，H02 与 C02 控制输入和产物，K01 与 K02 定义并检验成功，E05 与 I07 定位失败，M03 比较代价，R01 组织项目证据。

第二遍按目标职位选一个分支展开。例如 RAG 岗把 E05 延伸到混合检索、重排和分块；工具型 Agent 岗把 F01、I02 延伸到鉴权、持久状态和未知结果恢复。口述答案用于准备表达，独立实现、故障复现与实测结果仍应分别积累。
