## 这些材料反映的面试理解

小红书的不同作者表达了两类侧重。[Freya 的转岗讨论](https://www.xiaohongshu.com/explore/6a953e95000000001e016fd8)强调场景适配、限制、成本与项目闭环；[算法小登的评论](https://www.xiaohongshu.com/explore/6a159aa80000000035027199)强调题目随简历与项目变化，不能把固定题单当作覆盖承诺。另一方面，[Offer面试官发布的题单](https://www.xiaohongshu.com/explore/69b65422000000001a0312bc)同时出现检索、记忆、工具安全与数据库、限流，提示应用岗位仍需要传统工程基础。这些是具体作者和帖子样本，不概括所有博主或公司。

[牛客这则字节后端实习自述](https://www.nowcoder.com/discuss/932295617999622144)将混合检索一路追到 RRF、联合重排和领域迁移，再追问评测集与项目指标；[另一则迅雷自述](https://www.nowcoder.com/discuss/932392798559432704)把意图与记忆追问到“相似历史方案是否适用于现在”。从这两个样本看，准备到组件名称还不够，需要能说明何时有效、为何选它、哪里会错以及如何验证。它们不是公司统一面试标准，回答也不都是唯一解。

GitHub 的价值在于补全地图。[工具专题](https://github.com/05satyam/AI-ML/blob/main/interview-prep/genai-interview-questions/ai-agent-tools.md)适合补契约与执行边界，[Agent 基础整理](https://github.com/WeThinkIn/AIGC-Interview-Book/blob/main/AI%20Agent%E5%9F%BA%E7%A1%80/01_AIGC%E6%97%B6%E4%BB%A3AI%20Agent%E5%9F%BA%E7%A1%80%E9%AB%98%E9%A2%91%E8%80%83%E7%82%B9.md)适合查漏。整理型题库往往把不同岗位内容放在一起，所以这里将应用主线与专项分开；框架宣传、绝对化安全承诺和没有采样依据的高频比例不作为事实沿用。

X 上找到的可见索引涉及可复现评测、模型变化后的架构重审，以及语音 Agent 的追踪；正文访问返回 403，因此只转化为 A08、K07、Q08 的补充主题，不计为已核验面试原题。链接、读取层级和日期见来源文件 TW01 至 TW03。

我的综合判断是：有效准备应覆盖六件事——解释模型与 Agent 的分工，说明资料和工具怎样进入系统，控制状态与副作用，用数据判断是否成功，定位失败并改进，以及把技术选择放回实际业务约束。这个判断是对有限样本的归纳与工程建议，没有推算全网出题概率。

总出现数 = 去重面经来源数 + 去重公开题库来源数；重复次数 = max(总出现数 − 1, 0)。出现 1 次表示有一份匹配材料、重复 0 次；出现 0 次表示当前样本没有匹配证据，不代表题目不重要。

计数范围为3份面经题单与5组公开题库，73题有计数命中，47题至少在两份去重资料中命中；工程补充与未核验线索不会获得虚构次数。详细口径见来源文件。

## 需要防止的误解

- 检索命中一个片段，不等于证据覆盖了所有条件；向量相似不等于事实支持。
- Schema 或 Function Calling 不自动保证语义和权限正确；安全在执行边界落实。
- Checkpoint 不自动保证外部动作只执行一次；重试、恢复和幂等分别回答。
- 更多 Agent、上下文或工具，不自动带来更高任务收益；比较相同预算下的基线。
- 模型自评和公开榜单不代替业务评测；多次最好成绩不代替单次可靠性。
- 项目设计、离线验证和线上收益分别陈述，不能把模拟结果改写为真实经历。
