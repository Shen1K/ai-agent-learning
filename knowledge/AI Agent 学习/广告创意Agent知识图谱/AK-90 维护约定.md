# 知识图谱维护约定

维护目标是同一事实只保留一个主要入口，而不是承诺任何修改都只动一个文件。首版不使用社区插件、自动生成图谱服务或重型数据库。

## 内容归属

- 知识页：当前机制、边界和可验证主张。
- 案例页：当时的条件、判断、操作和结果，不抹掉历史。
- 视图页与Canvas：阅读入口、节点位置、关系与流程。
- 来源页：集中维护项目文件和公开依据。
- 项目学习进度：个人实际证据与下一课，不在此维护另一套。

2026-11-07第二轮整理后，旧课程及早期面试资料移入归档，保留历史内容；通用面试答案由144题主页面维护，已核对相同的副本改为链接。完整归属见 [[knowledge/00-index/主要维护页与归档规则]]；本试点知识页仍负责工程机制，不声称已经消除全库所有语义重复。

## 修改决策表

| 改什么 | 主要修改哪里 | 还要检查什么 |
|---|---|---|
| 定义、解释、边界 | 对应AK-K页 | 引用是否仍然成立 |
| 一次新观察或失败 | 新案例页 | 关联知识是否需要修订 |
| 模块间关系 | 对应视角Canvas | 相关知识关系字段与另一视角 |
| 来源路径 | AK-S01 | 本地链接是否可用 |
| 学习完成状态 | 项目learning-progress.md | 不复制到知识页 |
| 面试通用回答与追问 | 144题主维护页 | 24题、答案索引、精选题的引用与独有例子 |
| 节点改名或移动 | Obsidian内操作优先 | 全部wiki引用、Canvas路径与标题锚点 |

## 稳定标识与引用

全局关系图使用 `tag:#ai-main` 筛选核心知识；维护说明、来源、归档和重复答案索引不加这个标签。筛选只是展示控制，不删除内容，也不代替正文去重。

文件名保留AK编号；正文摘要保留稳定块标识summary，Canvas使用图谱摘要标题定位。不要删除仍被引用的锚点。知识页frontmatter中claim、human_explanation等字段是正文位置引用，不是另一份复制定义；depends_on、supports、derived_from采用带wiki链接的列表，方便Obsidian展示关系。

这是一版知识对象约定，不声称符合另一个尚未核验的外部schema。hypothesis表示整理主张待审阅；reviewed、validated只能依据实际审阅或验证升级，不等于本人掌握状态。

Obsidian自动更新文件链接的能力不能覆盖任意外部脚本、标题或语义变化。修改后仍需检查引用。Canvas文件节点引用原文件而非内嵌副本，文本改动后重新查看即可；连线标签和布局需要人工维护。

## 本次试点的更新演练

选AK-K09的图谱摘要，增加缺失检查项不默认通过的边界。检查系统视角、任务视角及案例中的引用都仍指向同一原段落，Canvas卡片仍引用同一来源，不手工改写这些引用处。

验证脚本还应在内存副本中模拟一次摘要更新，确认全部嵌入和Canvas目标均能解析新内容；这种检查证明引用结构一致，不替代Obsidian实际渲染检查。演练结果见 [[AK-91 结构检查记录]]。

## 新增知识的轻量流程

先找现有页能否补充；能补就不要拆新页。必须新增时分配稳定ID，保留来源、适用条件、反例及验证方法，选择少量有明确含义的关系，再决定是否值得进入主图。没有必要把每个术语都拆成节点。

## 暂缓的内容

问题选型、概念对照和迭代闭环三个新视角留待首版体验后扩展。当前两张Canvas与十个主题已覆盖主要入口，但不取代原课程全部细节。
