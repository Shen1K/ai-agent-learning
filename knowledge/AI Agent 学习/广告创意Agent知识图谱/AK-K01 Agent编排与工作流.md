# Agent编排与工作流

## 图谱摘要

Agent运行时根据模型提出的动作调用受控工具，保存状态，再把必要结果交给模型；固定工作流预先确定流程，二者可以在一个系统中组合。
^summary

## 适用场景

一次任务需要根据检索或评审结果改变下一步时，使用动态决策；已知必经检查则由程序固定执行。

## 核心机制

模型返回的是动作请求，不是直接运行程序。程序校验工具名、参数、权限与预算后执行，保存结果，再决定继续、等待输入还是结束。LangGraph属于编排候选，不是另一种大模型。

## 在项目中怎样使用

杯子任务中，模型可以选择查资料、保存候选或请求澄清；最终提交必须经过程序规定的检查。

## 边界与反例

离线脚本写死先生成再改稿，可以验证运行时分支，但不能证明真实模型会自主决策；固定工作流不是低级方案。

## 如何验证

给出两种不同反馈，检查模型或预定分支是否走向合理动作；分开记录真实模型决策与脚本模拟。
