# AI 全景与后续专题

工程地图第一轮先补全模块关系，再选择重点深入：每个模块讲清问题、输入输出、上下游、主要取舍与失败边界即可推进，不以逐字段实现或完整实验作为概览门槛。未验证项保留，实际接续位置见学习进度（本分享版未收录）。

现行课程：6 周核心方案（本分享版未收录）。本页在第一阶段就会使用；用途是建立位置与联系，详细推导和实现按需后移。

## 1. 先看懂整体

AI 是一个广泛领域；机器学习研究如何从数据中学习模型，深度学习是其中使用多层神经网络的一类方法。分类、预测、推荐、识别和生成是不同任务，不能全部化约为聊天。

本项目主要研究大模型与 Agent。语言模型根据上下文形成 token 概率并生成；Agent 是组织模型、工具和反馈的一种系统架构，不是所有 AI 的上位概念，也不等于强化学习。

把技术放到四层中理解：

| 层次 | 它负责什么 | 第一阶段深入的关系 | 周边专题 |
|---|---|---|---|
| 数据与学习 | 从样本中调整模型，并检查对新样本是否有效 | 样本、参数、损失、简单更新与泛化 | B01、B03、B04、B05、B15 |
| 表示与生成 | 将信息表示为可计算形式，利用历史形成预测 | 向量、参数共享、上下文和注意力直觉 | B02、B06、B07、B08、B12 |
| 行为与知识 | 让模型适应任务，并获得当前任务需要的信息 | 指令行为、当前上下文、外部资料 | B10、B11 |
| 系统与运行 | 把生成接到工具与业务流程，控制和验证执行 | 请求、工具、状态、反馈、停止、错误定位 | B09、B13、B14、B16 |

两条路径帮助定位每项技术：训练改变参数；使用时组织输入、运行模型、执行工具并处理结果。检索改变本轮可见资料，微调改变参数；两者可能配合，但作用位置不同。

## 2. 第一阶段就知道、以后再展开的内容

以下是主线周边的主要分支，不声称穷尽 AI 或精确占知识量的 80%。每项先知道“是什么、解决什么问题、在图中哪里、何时深入”，不用背全部缩写或掌握实现。

| 编号与主题 | 是什么、为什么存在 | 第一阶段了解到这里即可 | 后续深入的触发条件 |
|---|---|---|---|
| B01 经典机器学习 | 回归、分类、树模型、聚类等处理预测、判断和分组问题；任务与数据决定方法选择 | 区分有标签预测、无标签结构发现、生成任务；知道大模型不是所有问题的默认方案 | 遇到表格数据、评分、分类或推荐任务，需要选择基线 |
| B02 其他模型结构 | CNN 利用局部结构，RNN 逐步传递状态；状态空间模型、MoE 等采用不同的序列计算或参数使用方式 | 结构影响模型怎样利用信息和计算资源；了解存在替代方案即可 | 处理图像、长序列或算力限制，需比较具体结构 |
| B03 数据工程 | 清洗、标注、去重、采样和版本记录决定模型与评测究竟看到了什么 | 知道数据分布、质量和泄漏会影响结论；区分训练、验证、测试 | 成绩波动、数据扩大或结果无法复现时 |
| B04 统计平滑与回退 | 为稀少或未见事件分配更合理的概率；包含回退、插值、折扣等不同方案 | 理解为何纯计数会失败，以及缩短上下文会损失信息 | 需要解释统计模型性能或深入概率估计时 |
| B05 完整求导、优化与自动求导 | 反向传播高效计算多层参数的梯度；优化器选择更新方式；框架组织这些运算 | 懂一次简单更新；知道完整网络如何把误差传回参数以及框架代办什么 | 要修改网络、诊断训练不收敛或自己实现训练时 |
| B06 表示学习 | One-hot、Word2Vec、上下文表示和检索向量用不同目标表达对象及关系 | 向量的意义来自训练目标与数据；不同用途的 Embedding 不能直接混同 | 相似度检索不理想、需要选择或训练表示模型时 |
| B07 分词与数据编码 | tokenizer 将原始文本转换成模型使用的 token；字符级、子词等方案具有不同取舍 | 知道一个字符不一定等于一个 token，编码影响长度预算与输入形式 | 中文、代码、特殊符号或长输入出现处理问题时 |
| B08 Transformer 内部结构 | Q/K/V、多头、位置表示、残差、归一化和前馈层共同构成网络 | 能在整体图中指出各部分用途；第一阶段只算极小注意力，不推导全部矩阵 | 想修改模型结构、训练小 Transformer 或理解具体架构差异时 |
| B09 推理与性能 | KV cache 复用历史计算，量化减少数值表示开销，批处理组织多请求；速度、内存和质量需要取舍 | 知道性能问题有计算、内存和请求组织等来源 | 实际遇到延迟、内存、成本或并发问题时 |
| B10 微调与后训练 | SFT 使用示范任务调整行为；LoRA 是减少可训练参数的一种适配方法；偏好优化利用偏好信号 | 知道它们改变参数，目的与仅补充上下文不同；不把行为改善等同于事实保证 | 输入与资料已改善，但仍有稳定任务行为缺口，且有可用训练数据时 |
| B11 进阶检索 | 切分、混合检索、重排序和向量索引改善证据的发现与选取 | 理解“先找到证据，再让模型使用”；检索分数不是答案正确率 | 文档增多、正确证据经常检不出或输入预算不足时 |
| B12 多模态与生成 | 视觉、语音、文本可由不同编码和生成机制处理；扩散模型通过逐步去噪生成样本 | 知道不同模态与目标需要不同机制，不能把所有生成都解释成文字续写 | 任务需要图片、音频、视频或跨模态理解时 |
| B13 复杂 Agent | 规划、重规划、长期记忆、恢复和多 Agent 协作为较复杂任务组织执行 | 知道它们分别处理步骤、信息保存、失败恢复与分工，也增加复杂性 | 单个受控流程确实无法完成任务，并有评测依据时 |
| B14 协议与框架 | 工具连接协议统一接口，框架组织调用、状态与流程；MCP 是此类协议中的一个 | 能区别模型能力、连接规范与编排实现；框架并不替代理解调用过程 | 工具或系统集成数量增加，手写接口难维护时 |
| B15 强化学习 | 通过行动、环境反馈和奖励学习策略，关注行为对后续结果的影响 | 知道它与监督学习的反馈不同；能调用工具的 Agent 不一定经过强化学习 | 研究连续决策、奖励设计、策略训练或相应后训练方法时 |
| B16 生产工程与完整评测 | 服务、部署、权限、日志、恢复、版本和系统化测试使应用可运行、可维护、可检查 | 第一阶段会做小样例与错误定位；了解生产系统还需要哪些层 | 有真实使用者、稳定性要求、发布或业务指标时 |

## 3. 怎样补充概览而不重新拖长课程

- C01：先说明全景关系，允许暂时只认识部分名字。
- 第 1 周：B01—B03，说明任务、结构和数据的关系。
- 第 2 周：B04—B06，说明概率方法、训练计算和表示学习的分工。
- 第 3 周：B07—B09，说明文本编码、模型结构和运行效率的分工。
- 第 4 周：B10—B12，说明改变参数、补充资料、扩展模态的区别。
- 第 5 周：B13—B15，说明编排复杂度、连接规范和策略学习的区别。
- 第 6 周：B16，回访全图，选择下一步真正需要的主题。

每周约 15 分钟，已经计入核心方案的 3—4 小时预算。每项用一个简短例子说明用途，不布置论文、完整推导或实现作业。理解检查只问“遇到哪类问题会想到它”，不要求记住所有细节。

概览的状态是“未介绍 / 已知道位置与用途 / 待深入”；只有实际讲过并核对理解才更新，不自动把写在本页的内容登记为已学。

## 4. 后续深入怎样启动

第一阶段完成后，由实际问题或本人兴趣选择一个专题，先安排 2—4 次课：回到问题与先修 → 推导必要机制 → 做最小实现或对照 → 检查是否解决了原问题，再决定是否继续扩展。

工程方向按现行方案中的项目主线（本分享版未收录）连接多个专题：业务、规则和案例由助手准备，学习者重点学习工程机制。B03/B11连接数据与检索，B13/B14/B16连接工具、状态和系统验证，B08/B10连接模型运行与适配，B09连接部署优化；这些是映射关系，不代表已授课或每个主题必须同时深入。开源参考按具体问题选取并核对模块，不以框架数量代表能力。

工程进阶当前面试优先：先建立目标工程岗位的完整技术地图，由项目问题引出原理、架构、方案比较和组件定位，助手直接给标准参考回答及递进追问答案。项目用于帮助理解和组织面试表达，不以代码开发顺序驱动授课；实现细节、部署与完整实验后置。原理解释的深度按面试追问展开，不等于只介绍术语；已经讲解与本人独立掌握仍分开记录，不把设计案例冒充真实上线经历。

| 下一阶段方向 | 首选专题 | 可以复用的旧详细材料 |
|---|---|---|
| 更深入理解或训练模型 | B05、B06、B08、B10 | 旧 S2/S3/S4 中相关课题，已经掌握的部分跳过 |
| 改进知识与检索系统 | B03、B06、B11 | 旧 S5 的检索及分层评测 |
| 构建更复杂、可靠的系统 | B09、B13、B14、B16 | 旧 S6/S7 的控制流、恢复与工程验证 |
| 扩展到其他 AI 任务 | B01、B02、B12、B15 | 另选针对性入门材料，不把语言模型课程生搬过去 |

旧 S/L 编号仅指 原详细课程参考（本分享版未收录），不计入当前 C01—C12 进度。新专题的原始论文、官方资料和实验范围在启动时确定。

课程目标是先拥有全局定位和核心判断，再按需要扩大解释深度；全景图可以持续扩展，不转化成新的全量必修清单。

广告创意项目的技术展开由项目生命周期驱动：发起问题与验收目标、最小基线与选型、模块实现、验证和优化。地图用于定位每个决策，不代替推导，也不把所有组件预设为必需；实现细节在对应章节讲解，面试表达贯穿各阶段。

广告创意项目从本人熟悉的brief、品牌资料、创意方向、文案／视觉方案和提案修改出发：B11用历史参考与品牌规范讲检索，B13/B14用创意生产步骤讲编排，B16用反馈与版本讲系统管理，B12连接视觉理解及图片生成。事实审核保留为支撑，不主导业务主题。实现主线为[广告创意Agent服务](<../creative_agent/README.md>)：模型根据反馈选择工具，程序负责执行边界、状态、恢复、预算和服务接口；先从文案闭环理解机制。已有局部实现及验证证据以学习进度（本分享版未收录）为准，不把整个能力地图视为已交付，也不将离线脚本替身等同真实模型实测。图片生成的机制和延迟指标不能直接套用语言模型的逐token推理；创意评价不等于投放效果，模型推测的受众洞察不能冒充调研事实。
