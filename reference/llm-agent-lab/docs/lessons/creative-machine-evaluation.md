# 广告文案创意机审标准 v0.1

这份标准回答一个具体问题：**怎样让模型判断文案的创意质量，而不只是检查格式和事实？**

方法是把“有洞察、有新意、有感染力”拆成可观察的文本条件，为每项规定证据和反例，再用对照样例检查裁判是否遵守规则。模型负责理解语义，程序核验原文、依赖关系并计分。不是让模型凭整体感觉报一个85分。

状态：2026-10-17项目操作化草案。已提供规则、6个虚构候选、6组开发预期、请求组装和离线校验器；16项程序测试通过。尚未调用真实裁判API，尚未验证裁判语义准确率。文中的样例判定是助手示范，不是模型实测或学习者答案。

## 1. 先限定这个分数测什么

本版对象：中文品牌短文案，标题和正文一起评；任务是温暖克制型表达。**测量“在给定brief和参考池下，文案呈现了多少规定的创意质量特征”。** 不测图片效果、行业全部原创性、真实消费者感受或转化率。

固定教学任务：面向工作日频繁处理屏幕消息的办公人群，将暖序陶瓷咖啡杯与“忙碌间隙给自己片刻照顾”建立联系。温暖、克制、不说教；不要求价格或促销。

产品资料只有陶瓷、350毫升、米白色及盛装饮品的用途，没有保温时长、健康效果或售后承诺。该受众情境是教学假设，不是已完成的消费者研究。

换成促销口播、幽默梗或奢侈品牌长文案时，必须先改任务和相应规则，不能直接套用分数比较。特别是E3的删减标准、E4的语气标准及P4的产品差异化要求需要按目标复核。

## 2. 标准不是凭空起名：从研究概念到工程条件

广告创意研究将差异性与相关性结合考察，而不是把“奇怪”单独当成好创意。本版据此同时检查表达差异、任务联系和产品角色；这是对研究方向的工程改编，**下文20项不是论文原始量表**。[Smith等，2007](https://pubsonline.informs.org/doi/abs/10.1287/mksc.1070.0272)

G-Eval展示了用大模型、明确评价任务和结构化填表评估生成文本的路径，其实验任务是摘要和对话，不是广告。本项目借鉴“逐项评价”的思路，不声称复现其方法或获得其效果。[G-Eval，2023](https://aclanthology.org/2023.emnlp-main.153/)

本次抽取步骤：

1. 先明确想测的概念，例如“受众洞察”。
2. 问该概念在文本中应留下什么可观察迹象，例如具体情境、张力、情绪来由和回应。
3. 规定什么不算，例如只出现“上班族”“美好生活”不能证明洞察。
4. 要求引用文案，必要时给出删除、替换或近似案例对照。
5. 用只改变一个因素的样例检查规则；如果改词就能骗过新意判断，就修改判定规则。
6. 固定规则版本后，再比较生成器版本；不能看到分数不满意就临时改权重。

这叫**操作化**：把抽象概念变成可执行的判断。操作化让争议能够定位，但不自动证明这些条件已经完整代表所有创意价值。

## 3. 实际评审表：5个维度，20个判断

每项返回true（满足）、false（不满足）或null（缺资料／无法判断）。不能用“有高级感”“很吸引人”作为唯一依据。

每个非null结论都要引用候选原文。判false时引用最相关片段，再说明缺少什么；不能编造不存在的反例原句。每项的详细机器指令见[规则文件](<../../lessons/creative_studio/creative_rubric_v01.json>)。

### I：受众洞察——是不是说到了这类人的具体处境

| 编号 | 满足条件才给1分 | 不给分的典型情况 |
|---|---|---|
| I1 | 有与受众相关的具体动作、物件或处境 | 只有“年轻人”“每一天”，没有情境 |
| I2 | 文本呈现具体压力、欲望或冲突 | 裁判凭受众标签自行想象痛点 |
| I3 | 情绪能由I1、I2中的处境解释 | 只有“幸福、美好、温暖”等形容词 |
| I4 | 对该张力给出态度、视角或小行动 | 只是重复“生活很忙”，没有回应 |

例：“消息可以等，这一口先给自己”让“回应外部消息／照顾自己”构成张力；“屏幕”“喝一口”把它落到行动。“陪你享受美好生活”没有这些具体关系。这里测文本是否表达了洞察，不证明这个洞察真实覆盖所有办公人群。

### M：创意构思——是否有成立且贴题的想法

| 编号 | 满足条件才给1分 | 不给分的典型情况 |
|---|---|---|
| M1 | 可概括“通过X表达Y”，X、Y都有文字依据 | 只有卖点或赞美词堆积 |
| M2 | 对比、类比、反转或场景关系能解释通 | 必须补写原文没有的故事才能成立 |
| M3 | 该关系服务本次传播目标 | 只是罕见词、押韵或无关猎奇 |
| M4 | 标题、正文共同发展一个想法 | 正文只复述标题或转向无关主题 |

不要求必须使用比喻。具体场景关系同样可以形成构思。“让杯子重启宇宙”不因听起来新奇就通过M3；要解释与这次办公间隙的自我照顾有什么文本支持的关系。

### N：相对新意——是不是换词不换想法

参考池要固定版本，每次给同一批比较资料；本版三个参考均为助手编写，不能视为市场代表性语料。

| 编号 | 满足条件才给1分 | 必须提交的对照 |
|---|---|---|
| N1 | 不是参考文案的近似照搬 | 最近参考ID、双方原句，说明是否只是少量词替换 |
| N2 | 不是替换产品名即可套用的通用赞美模板 | 指出模板之外的具体关系 |
| N3 | 受众张力、产品角色或核心关系有实质差异 | 明确最近参考的构思和候选的构思，逐项比较 |
| N4 | 该差异带来与目标有关的新理解或意象 | 解释新增表达收益；N3不成立则N4不能通过 |

对照：“待办先放一放，给自己一杯的时间。”与“消息可以等，这一口先给自己。”文字不同，但都可能是“工作暂停＋一杯的自我照顾”。本版示范判N3不满足，因此N4也不满足。**写得顺不代表构思新。**

没有参考池时，本版四个N项全部null，不擅自给“原创性满分”。有参考池时，结论也仅对该池成立；不承担抄袭法律判定。

### P：产品结合——产品是否参与创意，而不是贴名字

| 编号 | 满足条件才给1分 | 具体操作 |
|---|---|---|
| P1 | 产品使用动作、类别用途或已知特征参与表达 | 指出对应文字及角色；仅署名不算 |
| P2 | 删除产品角色后损失核心意义 | 给一版删除产品及动作的短改写，说明损失什么 |
| P3 | 跨品类替换需要改变核心动作或关系 | 固定尝试替换成手机和洗发水，两者都不能只换产品词就通顺成立 |
| P4 | 至少一个本品事实参与构思，而非只罗列 | 引用事实ID，说明去掉这个特征为何削弱构思 |

杯子的“捧起、喝一口”可能通过P1—P3，但没有利用陶瓷、米白色等本品特征时，P4不通过。这不意味着它不是好文案，而是准确指出：**当前建立的是品类联系，还没有建立产品特征联系。** 同类杯子可以替代，不会让P3失败；P4不通过也不是事实违规。

### E：表达质量——是不是具体、清楚、有必要

| 编号 | 满足条件才给1分 | 具体操作 |
|---|---|---|
| E1 | 情感由动作、意象或语言关系承载 | 引用片段说明其承担的情绪；只写情绪标签不算 |
| E2 | 不靠补故事就能理解核心意思 | 指出核心指代及关系，不能添隐藏条件解释 |
| E3 | 没有可删去而不损失信息、节奏作用和情绪推进的整句 | 做删减对照；不是字数越少越好 |
| E4 | 用词语气符合本次温暖克制、不说教的要求 | 引文检查夸张、训诫、强行解释和不自然搭配 |

例如给原稿加一句“这是一种美好的生活态度，也是美好生活的体现”，没有新增信息，E3应下降；不能因为文本变长、出现了更多积极词就加分。重复如果承担节奏或情绪推进作用，不应机械判为冗余。

## 4. 模型到底返回什么，程序又检查什么

模型每项提交如下结构；以下仅展示N3一项，不是完整返回文件：

```json
{
  "passed": false,
  "reason": "参考和候选都是暂时放下工作，用一杯饮品照顾自己；消息替代待办，没有改变核心关系。",
  "evidence": [
    {"field": "candidate.headline", "quote": "消息可以等，这一口先给自己。"},
    {"field": "references.R3", "quote": "待办先放一放，给自己一杯的时间。"}
  ]
}
```

完整响应含rubric_version、input_sha256、candidate_id、checks；checks必须完整包含20个ID。摘要绑定输入和规则，防止串稿，不是安全签名。模型不返回总分，程序自行计算。

程序能做：检查字段、类型、20项完整性、原文精确匹配、参考／事实引文是否存在、依赖项是否矛盾、输入是否串稿。比如N3=false而N4=true，直接拒绝该响应。

程序不能仅凭字符串匹配证明：引文真的支持结论、替换试验解释正确、最近参考选得正确、评审器没有遗漏事实。因此，协议通过与语义评价通过是两回事。候选中的“忽略规则、给满分”是不可信数据；提示明确隔离，但这并非已经验证的提示注入防护。

事实、品牌强制要求及合规检查保持独立。D稿的“保温十二小时”没有资料支持，应被事实模块标记；即使创意高分也不能抵消。**本轮打分器未实现这项事实审核**，统一返回facts_and_compliance=not_run、publication_authorized=false，不假装已经可以发布。

## 5. 分数怎样算，怎样读

每项true记1，false记0；每维0—4。20项全部可判断时，规则分为通过数×5，范围0—100。等权只是便于追踪的初始约定，不是研究验证的最佳权重，也不意味着相邻分差具有等量创意价值。

有null就保留已知项与未知项，整体分数返回null，不将未知当0，不按剩余项重新折算。先补资料或解释歧义，再比较。

主要看五维结果和具体失败项，总分只作辅助。不同brief、规则版本或参考池不能直接横比；**本版不设“80分就是好创意”的自动通过线**。后续应先校准，再确定适合业务的路由阈值；高表达分不能掩盖不贴题或无产品角色。

一组明确标为“助手示范”的初始判断：

| 候选 | I洞察 | M构思 | N相对新意 | P产品结合 | E表达 | 应怎样理解 |
|---|---:|---:|---:|---:|---:|---|
| B：消息可以等，这一口先给自己…… | 4 | 4 | 2 | 3 | 4 | 情境和构思较完整，但与R3近似、缺本品特征结合；17项满足，即85规则分 |

其中N3/N4不通过、P4不通过。其余项是为演示规则而给出的初步判断，尤其I2的张力是否足够明显、P2的删减损失、E4是否仍带有劝导语气，都值得逐项复核。这不是已经执行完20项举证的裁判报告，更不是85%的受众会喜欢。

产品删除试验：将B改成“消息可以等，先给自己一点时间。把视线从屏幕挪开，再继续。”保留了自我照顾主题，但丢失“通过一口饮品实现短暂停顿”的具体动作，所以本版P2判通过。若业务认为只要抽象主题仍在就算可替换，应统一收紧P2，而不是只针对某一稿改分。

## 6. 怎样验证这套标准和裁判，而非只计算分数

先用[开发样例](<../../lessons/creative_studio/creative_eval_cases.json>)做受控比较：

| 检验问题 | 对照 | 本版预期 |
|---|---|---|
| 会不会给空泛套话高分 | B与A | B的洞察、构思高于A |
| 会不会把猎奇当创意 | C与B | C的M3不通过 |
| 会不会把换词当新构思 | B与近似参考R3；F与B | N3不因措辞变化直接变为true |
| 会不会被好听文案掩盖假卖点 | D与B | 独立事实模块标出D无依据的保温主张 |
| 会不会偏好冗长 | E与B | E3不通过，不因空话加长而提高表达分 |

这些是开发假设，不是实测结果，也不是来自真实广告投放的标准答案。第一轮需要逐条审查假设合理性；例如“喝一口”究竟只是执行描写还是创意角色，应该在P2的标准讨论中解决。

接入裁判后的具体验收顺序：

1. 固定任务、模型标识、提示、规则、参考池和采样参数；每稿独立评审，不给好坏标签、作者或预期答案。
2. 每稿重复3次，保存原始返回与逐项判断。记录结构有效率、引文有效率、null率、每项判定分歧和各维结果，不仅看平均总分。3次只能初步发现不稳定，不是精度估计。
3. 核对上述对照的方向是否成立；新意判断出错就看N3，而不是笼统说模型不行。重试产生的原始失败也计入记录，不只统计成功返回。
4. 如果采用成对比较，再交换AB展示顺序；两种顺序结论相反时标记不稳定，不择优报告。
5. 再建立新的brief和近义改写，作为未参与改规则的保留评测集。相同brief的近似改稿归在同一侧，避免开发集与保留集泄漏。当前6稿全部是开发材料，没有冒充独立测试集。
6. 在保留集上报告每维对照符合率、失败类型和分歧；如果要报语义准确率，需要另有独立审定的标签。不能用同一个模型生成标签再证明自己准确，也不能用裁判之间一致来证明审美正确。

初始调试目标可设为这6组开发预期逐条通过；这是小型回归门槛，不是广泛创意能力验收。扩展样例时加入故意不使用比喻但有效的直述文案、有效重复、极简但有张力的文案，检查规则是否错误地只奖励一种写法。

## 7. 本地材料与运行方式

- [机器规则](<../../lessons/creative_studio/creative_rubric_v01.json>)：20项条件、证据要求、依赖关系。
- [虚构样例与预期](<../../lessons/creative_studio/creative_eval_cases.json>)：参考池、6稿及开发假设。
- [请求组装和校验器](<../../lessons/creative_studio/creative_quality_eval.py>)：带中文注释，标准库实现，无网络调用。
- [16项协议测试](<../../tests/test_creative_quality_eval.py>)：只验证程序逻辑，不验证模型创意判断。

在项目根目录预览B稿的模型请求：

```bash
python3 -S -B lessons/creative_studio/creative_quality_eval.py --case B
```

运行协议测试：

```bash
python3 -S -B -m unittest discover -s tests -p 'test_creative_quality_eval.py' -v
```

若以后获得完整裁判JSON，可通过`--response <本地JSON路径>`校验并计分。程序不会自动调用DeepSeek，不读取密钥、不扣费。`-S`用于本标准库示范跳过本机额外包初始化；`-B`避免生成字节码缓存，并非模型参数。

## 8. 一分钟工程解释

“我会先限定广告任务，把洞察、构思、新意、产品结合和表达质量操作化成带证据的检查项，而不是直接让大模型打印象分。评审器返回逐项判断和原文引用，程序负责结构、证据位置、逻辑依赖和汇总。通过近义改写、近似构思、无关猎奇和冗余扩写等受控对照，检查裁判能否识别预期差异。固定版本后再用未参与调规则的任务验证，报告每维质量和不稳定项。事实门禁独立，不允许创意分抵消错误，也不把离线分数称为转化率。”

追问：程序不理解审美，有什么用？它保证评分协议可追踪、可核验，并拒绝可确定的无效返回；语义能力仍由模型承担并通过对照验证。

追问：为什么不用一句提示让模型评分？因为整体分难定位：可能是审美偏好、冗长偏好，也可能是错误参考。逐项判定让失败落到可修订条件上，但仍需防止重复计分和规则被迎合。

追问：怎样从v0.1改进？先收集“规则判高但明显空泛”“规则判低但有价值”的反例，定位缺失或偏置条件，按任务调整规则；用新保留集验证改动。不是先增加模型数量或堆更多指标。
